# LOOKWALK E‑Commerce Site Documentation

## Overview
The **LOOKWALK** project is a modern React + Vite front‑end with an Express API back‑end backed by a single PostgreSQL database (hosted on Supabase/Neon). The architecture has been refactored to replace multiple storage solutions (localStorage, Firebase, SQLite) with a unified, secure data layer.

## How It Works
| Layer | Responsibility |
|-------|-----------------|
| **Front‑end (React/Vite)** | Renders UI, fetches data via `src/data/apiService.js`. Stores JWT in `sessionStorage` and attaches it to `Authorization` headers. Uses `src/utils/seo.js` for dynamic meta‑tags. |
| **Back‑end (Express)** | Provides RESTful endpoints (`/api/auth`, `/api/products`, `/api/orders`, …). Secured with Helmet, rate limiting, CORS, and JWT verification. All DB calls go through a single PostgreSQL pool (`server/db.js`). |
| **Database (PostgreSQL)** | Central source of truth for products, orders, users, settings, contacts, and categories. JSONB columns are used for flexible settings objects. |
| **Deployment** | Front‑end hosted on Vercel, back‑end on Render (or Railway). Environment variables (`VITE_API_URL`, `DATABASE_URL`, `JWT_SECRET`, etc.) drive configuration. |

## Key Improvements Over Original Implementation
* Consolidated data storage – **single PostgreSQL** replaces localStorage, Firebase, and SQLite.
* Added **JWT‑based authentication** and hardened admin login with bcrypt hashes.
* Centralised API client (`apiService.js`) removes duplicate request logic.
* Security middlewares (Helmet, rate‑limiting) and CORS restrictions.
* SEO utilities and dynamic meta‑tags for better discoverability.
* Simplified deployment workflow with clear env‑var mapping.

## Getting Started (Developer)
1. **Install dependencies**
   ```bash
   npm install
   ```
2. **Create a `.env`** based on `.env.example` – set `DATABASE_URL`, `JWT_SECRET`, and any other required keys.
3. **Run the migration** (if you have an existing `lookwalk.db` SQLite file):
   ```bash
   node server/migrate.js
   ```
4. **Start development servers**
   ```bash
   # Terminal 1 – Backend
   cd server && npm run dev   # runs `node index.js`
   # Terminal 2 – Front‑end
   npm run dev   # Vite dev server at http://localhost:5173
   ```
5. Open the app in the browser and log in with the admin credentials defined in the database.

## FAQ
* **Where are product images stored?** – Images are uploaded via the admin panel to the `public/assets/` folder and referenced by URL.
* **How to add a new environment (staging, production)?** – Duplicate `.env.example` as `.env.staging` / `.env.production` and point your deployment platform to the appropriate file.
* **Can I switch to another DB provider?** – Yes, just change the `DATABASE_URL` to the new provider's connection string; the schema is standard PostgreSQL.
